## 4. Verdict

The app is distributed as a sideloaded Android APK (plus the owner's own iPhone builds); it will not go to Google Play or the App Store, so store rules don't apply.

**Ship** — on one condition: the owner accepts P0-1 (public signing key) as a known risk, or decides to rotate it. Every fix kept in this pass is covered by a test that fails on the old code, and CI builds the Android release APK and an iOS Release build.

### Remaining risks, most serious first

1. **P0-1 public signing key.** Anyone can make an APK that installs as an update and gets this app's data. This needs an owner decision.
2. **No crash reporting (P1-3).** Production crashes stay invisible. Needs a Sentry (or similar) account.
3. **Nothing has been run on a device.** Not checked: the Maestro flow, memory over 20 open/close cycles, cold start, page-turn smoothness, the dark-mode flash, and the Hermes timings for 1000+ books.
4. **RTL books (P1-4)** display and select incorrectly.
5. **No backup or export of the library (P2-9).** Reinstalling or moving to a new phone loses books, highlights and notes.
6. **The Google Translate endpoint is unofficial (P2-7)** and can stop working at any time.
7. **Storage format has no schema version (P2-10).** A future change to how books are converted can shift highlights to the wrong place in existing books.
8. **iOS can't receive books from other apps (P2-11).** Only the Add button works.
9. **`npm audit` reports 5 high issues (P2-8).** All are in build tooling, not in the app; they go away with the next Expo 58 patch.
10. **Screen-reader users can't turn pages in page mode (P1-2)** — left as is by the owner's choice; scroll mode works with screen readers.

## 5. Layout sweep (2026-10-24)

Prompted by a real bug the tests didn't catch: the **search panel went off the top of the screen when the keyboard opened** (an 85%-high sheet pushed up by the keyboard). The jest renderer has no layout, so no test could see it.

`test/ui/layout/` now lays out the real rendered screens with **Yoga** (`yoga-layout`, the engine React Native uses; dev dependency only) and checks every button, text box and label on:
iPhone 15, iPhone SE, a small Android phone, iPhone 15 landscape and an iPad, each at text size ×1, ×1.35 and ×2, and with the keyboard open whenever a text box is on screen (iOS: `KeyboardAvoidingView` padding; Android: window shrinks).
It flags elements that are off screen or under the status bar/notch, behind the keyboard, clipped by their container, spilling out of a fixed-size card, or on top of another button or text.

Covered: the reader page and menu, all four Display tabs, contents/bookmarks/highlights, search (empty and with results), go to page, highlight tool, auto page turn, back chip, tap-zone guide, scroll mode; the library (grid, list, empty, every update-banner state, "adding book"), book details, highlights & notes, pop-up menus, the rename prompt, reading stats, dictionary and translation, the selection menu at all four corners and the middle, and the error screen.

Found and fixed. Every row was confirmed by running the sweep on the original files: it fails there and passes now.

| Problem | Where | Fix |
|---|---|---|
| Search box pushed above the screen when the keyboard opens | every device | bottom sheets stay below the status bar and shrink above the keyboard (`src/ui/Sheet.tsx`) |
| Long pop-up menus run off the bottom (no scrolling) | iPhone SE at normal text; other phones at larger text; landscape | menus and prompts scroll (`Sheet scroll`, `src/ui/dialogs.tsx`) |
| Reading stats run off the bottom | landscape; small phones at larger text | scrolls (`src/ui/StatsSheet.tsx`) |
| Error screen: button off the bottom, title off the top, under the notch | landscape; large text | scrolls, padded by the safe area (`src/ui/ErrorScreen.tsx`) |
| Display panel tabs and Close button under the notch | landscape | panel padded by the side insets (`src/reader/DisplayPanel.tsx`) |
| Go to page: number box and buttons behind the keyboard / off the bottom | landscape | card scrolls, tighter spacing on short screens (`src/reader/GoToSheet.tsx`) |
| Rename prompt buttons behind the keyboard | landscape | scrolls (see menus) |
| Font names and theme names spill out of their cards | text size ×2 | cards grow with their text (`minHeight`) |

**Not covered (NOT VERIFIED):**
- The native navigation bar and the library's search field (drawn by iOS/Android, not React).
- The book text itself, which is paginated by the phone's own text measurement.

## 7. Third pass: the reader moved to a WebView (2026-10-25)

On `main`, left uncommitted for the owner. Owner decisions: draw the pages in a WebView with the app's own small renderer (not Readium or foliate-js), replace the native reader directly, and keep every feature in the first version.

Why: the app drew its own selection handles over native text and had to guess where the phone draws each letter. On iPhone (TextKit justification) the guess was off by up to 180 pt. In a WebView the browser draws the text and its own selection handles, on both phones.

### What changed

- `src/reader/web/`: blocks as HTML (`html.ts`), the look as CSS (`css.ts`, same values as before), where the text goes (`frame.ts`), bundled fonts copied where the WebView can read them (`webFonts.ts`), the messages (`protocol.ts`), `WebReader.tsx`.
- The page inside the WebView is `src/reader/web/page/`. Page mode lays each chunk out in CSS columns one page wide; scroll mode stacks chunks. It handles touches, the browser's own selection, and marks (CSS Custom Highlight API, with a fallback). It is built into `page.generated.ts` with `npm run build:page`, and a test fails if that file is stale.
- **Removed:** `PageReader`, `ScrollReader`, `Measurer`, `paginate`, `CharProbe`, `charWidths`, `hitTest`, `metrics`, `drawnLayout`, `SelectionHandles`, `geometry`, the `modules/text-layout` native module (Android and iOS), and `bench/textkit`. The §6 row "iPhone selection handles" no longer applies.
- **Unchanged:** conversion, the block/chunk format, positions (block + character), highlights and notes, page numbers (estimated per chunk).

### Security

- Book text reaches the page only as HTML the app builds, with every text escaped (`escapeHtml`), and the converter still drops scripts and styles.
- The WebView may only load `file:` and `about:` URLs (`onShouldStartLoadWithRequest`). It opens no new windows and shows no link previews.
- On iPhone it may read files only inside the app's documents folder (`allowingReadAccessToURL`). On Android, file access is on, so the page can load the book's pictures and fonts. Any file the app can read is then open to the page's script, which is safe only because no book code runs there.
